# 工作台与 worker 的关系

记录日期：2026-10-22。

## 先理解两个名称

- **工作台（网站）**：供人操作的页面，用来创建任务、查看进度、浏览结果和导出数据。
- **worker（后台采集程序）**：接收任务并实际执行采集的程序，负责搜索 Google、处理返回结果、保存数据和更新任务状态。

网站和 worker 是两个独立运行的服务，可以部署在不同服务器上。

## 点击开始后，任务怎么执行

以一次 Google Web 采集为例：

1. 用户打开新服务器上的工作台，填写关键词，点击“创建并开始采集”。
2. 网站把关键词、来源、地区、页数等任务参数保存到原服务器的 PostgreSQL 数据库，并把任务 ID 放进 Valkey 任务队列。
3. 原服务器上的 worker 从队列取出任务 ID，再从数据库读取任务参数和运行状态。
4. worker 调用 OpenSERP，并通过代理中转访问 Google，获取搜索结果。
5. worker 将标题、链接、摘要、排名和请求状态等信息写入同一个数据库，按规则规范化 URL 并对历史链接去重。
6. 网站读取数据库里的任务状态和结果，显示在任务列表与数据集页面，用户可以查看和导出。

```text
用户的浏览器
    ↓ 创建任务、查看结果
工作台网站（20.150.145.162）
    ↓ 专用 SSH 加密隧道
数据库 + 任务队列（20.106.103.139）
    ↓ worker 取任务、读取参数
后台采集程序（20.106.103.139）
    ↓ 调用 OpenSERP 和代理执行 Google 搜索
搜索结果写回数据库 → 工作台读取并展示
```

可以把网站理解为“操作台”，把 worker 理解为“执行采集的工作人员”，队列是“待办清单”，数据库是“任务与结果档案”。网站通过共享数据库和队列与 worker 协作，不是在浏览器里直接运行采集程序。

## 两台服务器如何连接

新服务器使用专用、受限的 SSH 密钥建立加密隧道，连接原服务器的数据库、队列和搜索服务。相关转发端口仅在回环地址监听，没有为此次迁移把数据库和队列端口开放到公网。

新网站和原 worker 使用同一份任务与结果数据，没有另外建立一份独立数据库。因此网站迁移后仍能查看原有历史数据，原 worker 写入的新结果也能在新网站看到。

当前工作台依赖两台服务器及其连接：新服务器负责页面访问，原服务器负责执行采集和保存数据。

2026-10-22 已通过 Playwright 浏览器自动化直接访问公网工作台，创建手动一次性 Google Web 任务：

- 任务 ID：`86784589-c680-48ce-ac38-6fa857d332fd`。
- 关键词：`Singapore renewable energy research October 2026`。
- 原 worker 完成 1 次真实非缓存 Google 搜索，任务自动结束。
- 保存 9 条自然搜索结果，其中 8 个为历史去重后的新链接。
- 浏览器能够查看本次结果，并成功下载 CSV，核对为 44 列、9 条结果。

这验证了“新网站创建任务 → 原 worker 执行 → 数据保存 → 新网站展示与导出”的链路。

测试结束时，自动采集、正文采集、Whale 平台任务领取和上传均保持关闭。本次手动测试没有开启持续采集，也没有测试新结果上传到 Marsyoo；平台同步属于另一条流程。
