# Google Web 随机关键词词池调研

Google Web 固定采集前 11 页。目标是每个实际墙钟小时经历史去重并获中台入库确认的新增唯一 URL 数。词池改变搜索覆盖范围，URL 去重继续由现有历史库处理。

现有工作树的词池将 100 个主题、30 种意图、40 个地区做笛卡尔积。离线枚举了第一轮，得到 120,000 个不同字符串。顺序由固定步长计算，持续供给按 run ID 保留游标。词池用完会再次使用同组主题和意图，并追加日期过滤。手工关键词列表则按索引取模循环。因此，第一轮内部字符串唯一，但跨新 run、手工任务和词池版本的查询去重，需要单独的持久记录。

| 公开词源 | 适合的用途 | 使用条件与偏差 |
|---|---|---|
| [Wikidata 结构化标签](https://www.wikidata.org/wiki/Wikidata:Data_access/en) | 按类别提取公共机构、地点、工程项目、文化设施等实体标签，作为主词源 | [结构化数据 CC0](https://www.wikidata.org/wiki/Wikidata:Licensing)。按类别设配额，保留实体编号、语言与来源版本。 |
| [欧盟 ESCO 分类](https://esco.ec.europa.eu/en/about-esco/what-esco) | 补充职业和技能主题，可扩展多语言覆盖 | [官方复用规则](https://esco.ec.europa.eu/en/about-esco/faq)允许复用，要求署名并标明改编。主题集中在劳动力市场。 |
| [MS MARCO 和 ORCAS](https://microsoft.github.io/msmarco/TREC-Deep-Learning.html#license) | 研究真实搜索语句的结构 | 官方条款注明非商业研究用途。生产词池用许可明确适配生产用途的词源。 |

建议的供给流程：

1. 词源按版本快照保存。把实体标签与少量自然的搜索意图组合，以主题和语言为组交错抽样。固定随机种子和清单，便于复现。词池耗尽时扩充词源。
2. 对查询做 Unicode 规范化、统一大小写并合并空白。版本、任务编号及页码均不进入查询去重键。先用现有 Web 查询历史和已排队的 Web 任务填充去重账本，再以唯一约束原子领取新词。用户手动查词可以照常执行，执行记录要进入账本，供后续自动供给排除。第 2–11 页及失败重试复用原任务的进度。
3. 先做不发搜索请求的验收，覆盖两个任务实例、并发领取、进程重启和词池换版。再固定 11 页和并发配置，对照现有词池与公开词源词池。优先比较中台确认的历史新 URL／墙钟小时，同时观察查询复用率、历史 URL 重复率、各页覆盖和失败率。不同关键词仍可能落到相同站点和页面，不能仅靠词池判定产量提升。

调研阶段的证据来自公开词源官方说明和现有代码的离线枚举。生产部署与实测见下文。

## 首版实现和切换

首版使用 Wikidata 的 12 类英文标签。数据和许可见 [种子快照说明](../realtime/data/google_web_keyword_labels.README.md)。采集进程从本地版本化快照领取候选，不在运行时访问词源。PostgreSQL 账本按规范化查询的摘要去重，使用现有请求及任务记录回填。请求和任务触发器记录后续手动或实时 Web 查询。当前池启用时，每个自动任务只持有一个词，沿用分页进度和重试。词池耗尽时停止发词，导入新版本仍复用同一份历史账本。

初始化命令为 `python -m realtime.serp_keyword_pool --activate`，需在对应生产冻结 worker 内执行。切换前应停止自动采集、确认无在途、验证 Compose；旧自动任务需保留，避免把旧单页实验任务混入新的词池批次。冻结包通过复用现网 worker、只替换供给部分发布。本轮新 run ID 为 `google-web-random-20261118`，原 256 个自动任务保存为暂停，并留存 ID 和旧 Compose。验证产量时优先使用中台确认的新增唯一 URL、按页成功率和查询完成覆盖。

## 生产对账结果

| 方案 | 采集窗口 | 截止前中台确认 URL | 排空并读回后 URL | 最终请求成功率 |
|---|---:|---:|---:|---:|
| 首轮随机词池，18 槽 → 12 槽 → 18 槽 | 60 分钟 | 1,961 | 2,329 | 656 / 724，90.61% |
| 可运行队列与退避积压分开计数，18 槽 | 20 分钟 | 849 | 1,631 | 475 / 515，92.23% |

两轮共 1,131 篇快照验证通过，3,960 个历史新增唯一 URL 获确认，待确认和在途均为 0。第 2–11 页贡献 3,503 个。生产供给领取的 133 个规范化关键词无重复，66 个查询完成第 11 页。正文计数未变。

首轮 12 槽阶段承接退避积压，在 50 次请求中仅成功 36 次，按阈值退回 18 槽。这一阶段无法把并发因素与队列状态分开。新版为已退避的查询保留页码，限制未完成任务总数，并在全局熔断时停止补词。新版 20 分钟本地产量为 1,611，时段内中台确认 849。剩余回执在关停后继续处理。统计同时受查询组成、上游状态与中台排队影响，短期结果不足以确定长期产能最优。

留用新版调度、18 槽、Google Web 前 11 页。自动采集在复测结束后关闭，未启动持续运行。隔离 PostgreSQL 回归 48 项、4 子测试通过。对账见 `output/web-random-11p-20261118/audit.json` 和 `output/web-random-refill-20261118/audit.json`。生产回退 Compose 保存在两个对应 state 目录，恢复旧配置前应先确认自动采集关闭且无在途。
