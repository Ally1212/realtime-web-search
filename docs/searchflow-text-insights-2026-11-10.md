## 设计与范围

参考作者公开仓库 [bggg-skills](https://github.com/binggandata/bggg-skills)，研究版本 `1034ee5805f3fd5b010a4f57affa4aa796ab75d5`。可见 Amazon、Reddit、X 采集技能；仓库引用的 VOC 报告资源当时 404，不能宣称完整取得文章所述四个 Skill。Skill 是执行指引，不能直接作为网站运行时插件加载。本次将方法实现为独立 HTTP 服务、数据适配器和页面。

采用“固定样本 → 清洗去重 → 人工校准标签 → AI/规则标注 → 原文复核 → 确定性统计 → 报告包”的流程。AI 只提出标签与方面标注，数字由 Python 计算；不让模型自行计数或编造市场结论。

- **已有真实数据**：复用 `CustomerDataStore` 的公开/本客户/可访问范围谓词，只读已存标题与摘要；不发起搜索、不访问出版社、不启用采集。最多读取最新 100 个请求、5000 条记录，明确标记截取和统计分母。失败或空请求不伪造文本；没有文本时提示调整筛选。
- **VOC 数据**：导入 JSON、JSONL、含多行原文的 CSV，保存 source_id、原文、来源、URL、品牌、市场、星级、母帖等及附加源字段。真实评论与搜索内容分模式，后者不能作为用户体验或满意度证据。没有将新平台自动采集器接入生产。
- **解耦**：`realtime/insights_core.py` 为规则与统计核心；`insights.py` 为独立 SQLite 任务/快照/标注/审计；`insights_source.py` 为现有数据库适配；`insights_model.py` 为 Responses 适配；`insights_http.py`、`insights_schema.py`、`insights_server.py` 为 API；`insights_ui.py` 为界面及导航扩展。替换来源适配器即可复用于其他项目，不依赖旧采集协调器。

## 已实现

1. 固定输入快照和 SHA256、原生身份去重、母帖封顶并保留被排除原文、排除原因、缺失字段未知；已有搜索重复观察按规范 URL 与相同文本识别，保留 occurrence/request 证据。
2. 两套四级大类：VOC 固定“人群场景/功能价值/保障价值/体验价值”；搜索固定“主题议题/品牌产品/内容类型/需求线索”。二三级、判定说明和字面关键词可编辑，AI 草案必须人工确认。修改标签使旧标注失效并留审计。
3. 单工作线程持久队列、分批执行、取消、状态与调用台账、幂等意图、版本冲突保护、失败保留已验证批次；重启标记中断而非重放收费请求。人工复核记录受保护，相同文本/标签/方法/模型端点与名称/提示版本的已完成结果复用，包括“没有命中标签”的结果。
4. 方面情感和逐字证据起止位置检查；不存在或被改写的证据拒绝入库。人工可改标签、情感、证据与备注，或排除/恢复记录。证据存在只能证明片段真实，不能证明模型分类正确。
5. 标签频率及情感、品牌交叉、低星负面、来源/市场、可点击回查的主题排序、分母与限制。多标签比例可超过 100%，规则情感保持未知，缺失品牌/星级不推断。
6. JSON、JSONL、原文 CSV、统计 CSV、HTML、ZIP；完整包包含原文、源字段、标注、复核、输入版本、审计、模型调用/usage 台账和文件校验清单。输入、标注、台账与审计在同一 SQLite 读快照导出，ZIP 固定元数据；HTML 转义，CSV 防公式注入。

## 模型、权限与边界

使用用户指定的 Responses 兼容服务 `https://codex.veilo.dev/v1`、模型 `elastic-code`。私密配置仅服务器文件，权限 600；不传浏览器、不打印、不提交。按数据集显式允许外部处理后才发送文本。请求使用 `store=false`，但这不是对第三方服务保留政策的独立保证。

每批最多 10 条，每次最多 8000 输出 token；每任务 1–500 次调用上限，每空间 UTC 日预留上限 1000 次，已终止任务仍保留当日预留。模型请求前先记录调用次数；不自动重试、不跟随 HTTP 重定向。失败或取消的在途请求仍可能计费。记录供应商返回的 token usage，不提供金额报价或账单一致性保证。没有做数千条真实评论金标准确率或长期压力验收；长文本或复杂标签可能遭遇供应商上下文/输出限制，失败可见，不冒充完成。

全部 `/v1/insights/*` 需要网站访问门及客户 Bearer；OpenAPI 为 `/v1/insights/openapi.json`。租户隔离，派生读取/导出复查原请求的当前可见权限。删除只删除本分析数据集、任务和审计，不删除原始搜索数据；外部下载副本不能回收。分析不消耗 Google 搜索任务额度，但模型调用受独立次数限制，实际账单由供应商决定。

## 使用顺序

1. 打开“文本洞察”，沿用已连接的客户空间；未连接时使用原客户 Key。
2. 从已有搜索数据筛选创建，或导入有权分析的真实评论文件；按内容选择模式。
3. 生成或修改标签并人工确认，再选择 AI 或规则执行。
4. 点击主题回查原文并抽查标注，确认分母/排除项后下载报告。

Amazon/Reddit/X 等平台抓取器、第三方平台账号准入、全量评论取得和数据许可仍属独立采集工作，不能从本模块上线推断已经接通。当前模块已能处理实际网站历史数据及用户导入的真实评论。
