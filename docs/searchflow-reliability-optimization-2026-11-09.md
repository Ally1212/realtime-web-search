## 已实现并上线

- 修正单次任务完成条件：Web 队列没有到重试时间、其他来源尚无成功记录时，不再因为本批次没有报错就标成完成。达到明确成功预算仍可提前结束，预算不是“全部关键词都成功”的保证。
- 新建手动单次任务默认最多重试 3,600 秒，可通过 `options.retry_window_seconds` 设置 60–14,400 秒；从第一次执行开始计时，待启动草稿不消耗窗口。暂停/继续保留原窗口；手动重新启动清除旧窗口起点，仍遵守源和代理冷却。超时写入 `retry_window_exhausted`，不再发新请求。旧客户 API 的独立 15 分钟期限保留，不能把手动任务窗口当成 API 承诺。
- 创建任务支持可选 `Idempotency-Key`，同一标识和请求体复用原任务，不同请求体拒绝；事务锁覆盖并发创建。网页仅保存请求体 SHA-256 和随机标识，响应未确认时相同参数继续使用原标识，确认成功后清除。测试程序用标识摘要找回响应丢失时已创建的任务，不自动重放 POST。
- 新建图片单次任务遇到临时错误保留重试机会，不立即终止。沿用现有队列、速率与代理保护，没有为了成功率缩短 CAPTCHA/429 等冷却。
- `/api/serp/tasks/{id}/progress` 区分真实保存请求、缓存关联、等待重试、在途、成功及失败后恢复。私有任务返回 404；进度读取不解压全量源响应。证据超过 10,000 条明确截断，不据此判定完成。
- 网页任务详情展示等待和恢复状态，保持已展开详情以便每 10 秒刷新时继续阅读。结果相同筛选的并发读取复用同一请求，条件改变时允许新请求并拒绝旧结果覆盖。
- 私有来源缓存只能被原 campaign 复用，避免公开任务显示成功却读不到保存结果。
- 上线显式 `field_contract=prd-v1`：请求、结果、feature、话题字段保留来源、缺失原因与测量依据；旧默认接口及固定快照身份保留。结构化请求参数增加嵌套凭据过滤。导出 CLI 支持同一字段版本及图片来源。

## 重试与结果含义

普通 Web 页失败按原策略等待 60、120、240……秒，上限 3,600 秒；403/429/CAPTCHA 类等待 1,800 秒。代理和来源另有独立冷却，最早可重试时间不保证立即得到工作槽或可用代理。连续多次失败可进入更长冷却，有限任务窗口可能在此期间结束。

成功请求与新增链接分别计算。有效空结果是成功但链接为零；请求失败不冒充有效空结果。缓存关联不算新上游请求，重复 URL 不重复贡献新链接。进度中的恢复耗时以“首个失败完成到首次成功完成”为依据，不冒充完整请求延迟或源内容新鲜度。
