# Google 图片来源接入交接

## 最新澄清：复用已有图片能力，不开发新存储

已从正式 `/internal/ingest` 与 `/internal/attachments` 确认中台已有 `assets[]` 和 `cover_url/cover`。SearchFlow现已按既有字段适配：图片地址→assets[].url、缩略图→preview_url、已知尺寸→width/height，media_type=image、role=media；不把每张搜索图片当封面、不上传二进制。Consumer需assets以及固定版本载荷读取权限。

中台同事需要确认的剩余项是独立google_images来源及授权/派单是否支持，不是重新开发图片字段或图片存储。以下提到的存取支持均指确认和复用现有接口。

## 可直接转发的话术

我们希望把 SearchFlow 的 Google 图片搜索结果也保存到 Marsyoo：沿用已有数据集 `social_media_raw`，新增独立来源 `google_images`，与 `google_search/google_news/google_trends` 区分，不新建图片数据集。

SearchFlow 已有图片采集能力，负责提供图片地址、来源网页、缩略图、尺寸及查询信息；请中台侧增加来源识别、实时查询派单、入库与固定版本读取支持，并配置对应 Collector/Consumer 权限。2026-11-13 登录读取的正式 OpenAPI 中还没有 `google_images`。请确认下面的建议契约，完成后回传接口文档和测试权限，我们再联合验证实际保存、读回及 CSV/JSONL 导出。

## 请中台补齐或确认

1. **来源与数据集**：`SourcePlatform` 新增 `google_images`，覆盖实际请求校验、任务派发、注册/领取、入库、查询过滤及管理端授权选项，不能只改 OpenAPI 文案。继续使用 active 的 `social_media_raw`，不将图片标成 `google_search`。
2. **实时查询**：复用 `POST /v1/live-queries`，`resource_kind=content`，传关键词、地区、语言和 `max_items`；第一版只采第一页，最多20条。不需要增加图片二进制上传接口。
3. **权限**：专属 Collector 仅授予 `social_media_raw/google_images/live_query`；Consumer 授予该数据集和来源的实时查询、结果读取、固定版本/快照原始载荷读取。检查组织策略和应用授权两层。不要扩大为所有数据集或所有来源。
4. **存取闭环**：沿用 realtime bulk 入库、processing receipts、任务完成后的 document_ids、Consumer 固定版本读回。`queued` 只能表示受理，必须取得 `accepted/duplicate` 及 document_id/version_id；原始载荷需可读取并校验hash。
5. **原始载荷**：复用 `content.platform_payload` 保存完整结构化记录；如果版本接口不直接返回载荷，需要支持现有官方快照 payload batch-get 路径。请确认指标补充、规范化等行为不会让客户端无法核对最终版本hash。

## 数据语义与边界

| 字段/概念 | 含义与要求 |
|---|---|
| image_url | 图片地址，作为图片身份；完整保留合法公开URL及其参数，不按网页跟踪参数规则清洗合并 |
| source_url / source_page_url | 图片所在的来源网页，与图片地址分开保存；采集层用source_url，标准化输出用source_page_url |
| thumbnail | 缩略图地址，缺失则null |
| width / height | 上游提供的正整数尺寸；未提供则null，不推测 |
| title / snippet | 上游提供的标题与摘要；不冒充网页正文 |
| observed_order / rank_basis | 图片网格观察顺序，不能冒充网页自然搜索排名 |
| query / region / language | 保留查询条件；每次请求保留请求身份与采样时间 |
| source_fields | 保留清理敏感字段后的原始来源字段，便于核验与导出 |
| media_downloaded | false；本次只保存元数据，不下载原图或获取图片使用许可 |

SearchFlow 当前准备复用链接观察消息：`content_type=search_result`，`source.source_platform=google_images`，`content.source_url/canonical_url` 为图片地址，来源网页在原始结构化载荷内单独保存。请中台确认这套对象语义；如要求独立 image 类型，请先回传正式契约再调整，不能靠猜测上线。

同一次请求内相同图片URL只交付一次；不同图片URL不可因共有来源网页或参数清洗而误合并。相同图片在不同搜索请求中的出现保留各自观察记录。

## 联合验收标准

- 一次真实图片搜索：每条交付图片均有保存回执，Consumer按回执固定版本读回完整载荷，来源/数据集/任务身份及hash一致。
- CSV/JSONL逐条比较图片地址、来源网页、缩略图、尺寸和原始字段；不能用本地缓存替代中台读回结果冒充验收。
- 重放同一幂等键不重复采集/扣额度；换参数复用同一键应冲突；其他客户无法读取该任务。
- 权限不足、持久化失败、载荷缺失或hash不一致时明确失败，不伪装成功或空结果。
- 零结果处理需要双方确认：现有链接运行器对空结果明确报错，不宣称已保存空查询快照；若需零结果也成功持久化，应单独明确快照契约后实现。
