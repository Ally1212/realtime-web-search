# Google 中文采集提速与两小时验收方案

目标：提高每天新增、相关、正文有效、历史去重且成功上传 Whale 的数量。仅允许 Google 发现 URL；允许扩充关键词和时间范围。两小时目标参照线为 8,334 条 Whale 新增接收，对应 10 万/天，不能把未上传正文或重复回执计入。

## 已实施的方案

| 环节 | 原日量实验 | 本次 pipeline 实验 |
| --- | --- | --- |
| 正文执行 | 12 并发；每个 URL 启动一次 Python | 24 个按需启动的常驻子进程；单任务 65 秒硬截止，异常进程回收 |
| HTTP 会话 | 每请求新建 Session | 按 origin 复用连接池，每进程最多 64 个会话，淘汰时关闭 |
| robots | 随单篇进程结束丢弃 | 进程内缓存 6 小时，同域任务优先分配给已有缓存的空闲进程 |
| 域名调度 | 线程先入池，再等待域名 semaphore | 入执行器前检查单域最多 2 并发，其他域名可以继续占用空闲槽 |
| 搜索 | 同步搜索占用主循环 | 3 个独立搜索线程，各自持有连接；继续共享 PostgreSQL 全局 Google 配额与冷却 |
| 正文回收 | 搜索/上传返回后才补任务 | 主循环持续回收结果、补足空闲槽；搜索与上传慢时正文仍可运行 |
| 上传 | 最早每 20 秒一次，每批最多 25 条 | 独立上传线程，每秒检查，最多 50 条/批；心跳维持 20 秒，保留幂等和退避 |
| 历史去重 | 抓取后才判断历史 | 先跳过已知有效历史 URL，再做正文哈希去重；此前失败/无正文 URL 可重新尝试 |
| 失败复查 | 无正文通常 1 小时复查 | robots/404/不支持格式 24 小时，403/短文 6 小时，临时错误 1 小时 |
| 旧正文更新 | 6 小时复查 | 该实验改为 24 小时，优先新增；更新不算新增 |
| 查询供给 | 基础主题、事件、近期窗口、少量站点 | 保留以上分组，增加最近四个完整年份查询；从历史 Whale 接收记录选最多 60 个站点，每站 5 个主题 |
| 发布时间 | 少量 HTML/JSON-LD 字段 | 增加明确的 pubdate、publishdate、DC issued、Parsely、Sailthru、time pubdate；支持带时区 RFC 日期 |

实现复用现有 LiveFetcher、抽取/质量规则、Google 发现与代理健康、实验账本及 Whale 客户端。原 `legacy` 执行器保留，新增 `--executor pipeline` 开关，不必迁移技术栈。SQLite WAL 保留 FULL 耐久性；每个线程拥有独立连接，增加调度/文档 URL 索引，写入由 SQLite 串行化。

不改变正文至少 500 字符、AI 语境、非验证/导航页、非截断等质量门槛。不填造发布时间、不以修改时间或抓取时间替代发布时间。日期缺失仍单列，因此本次日期优化能恢复多少必须由实测回答。

## 实验设计

- 查询语言：中文；来源：Google Web；分页：每查询最多 11 页。现有正文规则允许中英文，相关性按自动质量规则判断；不将结果称为全部中文或已逐条人工验收。去重为规范化 URL 与正文 SHA-256 去重，未新增语义近重复检测。
- 时长：固定 2 小时，暂停、冷却或故障不延长截止时间。最多额外 2 分钟收尾，晚于截止的正文/回执单列。
- 历史基线：最新中文正式实验、此前中英正式实验、此次预检的有效正文 URL 与哈希，加生产库已有记录。此前无效记录不冒充已采集成果，也不会阻止修复后的有效首抓。
- 存储：独立实验目录与 Outbox，SQLite 放 Docker 原生卷；完整正文仅在待上传期间临时保留。源码复制为只读快照，运行期间不热改正式实验。
- 旧实验保持原有暂停/停止状态；不启动 collector 的外部任务认领，不冲刷旧 Outbox。
- 回压：新 URL 待抓队列约 1,500 条、Outbox 5,000 条上限。继续使用已有 Google 全局上限，搜索线程数不等于 RPS。

正式比较同时展示历史实验首两小时、历史最近两小时和全程平均值，并注明：搜索结果时间、查询范围及可用代理不同；新实验还排除了旧实验已取得的正文，因此不是严格随机 A/B。两小时结果不承诺持续日增量，达到参照线后仍需 24 小时和多日验收。

## 验证与监控

已完成 113 项自动化测试：本机 102 项通过、11 项因缺少数据库配置跳过；Docker 使用新建独立测试数据库，113 项全部通过。新增测试覆盖会话隔离/淘汰、严格日期语义、失败冷却、同域公平调度、常驻进程复用、卡死进程回收、搜索租约与历史 URL 提前过滤。

Docker 测试结束时出现 psycopg 连接池析构的 Python 3.14 退出警告，测试本身全部通过；这不是业务请求失败，正式实验仍需监控是否有运行期连接池异常。

预检 `preflight-pipeline-20260915`：约 13.6 秒，1 个查询页、2 次实际通道调用、11 个 URL、3 条有效新正文、1 条 Whale 接收、2 条缺少日期。小样本只证明链路可用。

监控以每分钟采样为基础，关注主指标 Whale 新增接收、待上传、日期缺失、正文并发占用、新 URL 供给、Google 成功/CAPTCHA、资源占用和心跳。若出现资源耗尽、持续运行错误或质量问题，停止该独立实验并保留证据，不删除历史记录。

## 运行与回退

新入口：

```text
python -m realtime.cli benchmark-google start
  --directory <独立原生卷目录> --output <独立输出目录>
  --hours 2 --languages zh --executor pipeline
  --body-workers 24 --search-workers 3 --whale --remote-only
  --baseline-run <历史实验目录> ...
```

统计入口沿用 <http://localhost:8091/stats>。通过同一 CLI 的 `status` / `pause` 查看或暂停；`resume` 只能在原截止前恢复，不能延时。新实验需要独立目录，旧目录保存的执行器配置不被命令行覆盖。

若回退执行器，新建目录选择 `--executor legacy` 即可；不把两种执行器结果混在同一正式实验中。两小时完成后在本目录另保存实测结果、指标快照和源码校验值。

## 固定快照之外的后续修复

实验期间发现：主 WML 成功返回空页，但用于确认空页的备用通道正处于冷却时，原调度将 `google_provider_cooling` 扩大为整个搜索流水线暂停 60 秒。账本中已有多次“唯一实际尝试为 WML success=true、results=0”的对应记录。工作区已修复为：保留该查询页未确认和延后重试，仅当没有任何成功的实际尝试时才设置这类全局暂停。Google 全局熔断、出口冷却和配额仍照常执行。

另发现浅层搜索页一小时后重新到期，消耗搜索预算；约 86 分钟时已重复成功搜索 881 个查询页。工作区已将 pipeline 成功查询页刷新间隔设为 24 小时，优先未访问页；失败页继续按原失败重试策略调度。这个取舍优先新增量，会降低同一查询日内刷新频率，不改变旧 legacy 执行器。

上述两项修复未写入本次运行的只读源码快照，因此不能把其潜在收益计入两小时实测。回归覆盖主通道空页与备用冷却、全部通道冷却、全局熔断、成功页延后及失败页及时重试；相关 55 项回归全部通过。后续容量变化需要新建实验测量。
