# SearchFlow 网站使用说明

更新日期：2026-11-13｜供同事直接使用和小范围测试

**网站地址：https://searchflow.20-150-145-162.sslip.io/#api**

这个网站用于查询 Google 网页、新闻、当前热搜和地图商家，查看结果并导出文件。**普通网页用户只需要网站访问 Key，不需要去中台创建应用或填写中台 Key。** 网站访问 Key 请向管理员领取，本文不附真实凭据。

## 一、第一次使用：先跑一个小查询

1. **登录网站**：打开上述地址，按提示输入网站访问 Key，进入工作台。
2. **打开“快速使用”**：选择“采集新数据”，第一次只勾选一个来源，例如“Google 网页”。
3. **填写条件**：输入 `sodium ion battery research`，选择“美国”和“英语”。
4. **点击“获取数据”**：等待任务完成。处理中不要重复创建相同查询；刷新后如出现“继续查看进度”，点击它恢复。
5. **查看结果**：核对标题、链接、摘要和来源；展开“查看完整响应 JSON”可看完整字段。
6. **下载文件**：点击结果对应的 CSV 或 JSONL 下载按钮。CSV适合用表格查看，JSONL适合交给程序处理。

批量查询时，关键词每行一个，可以选择多个来源；以页面显示的请求数量为准，每批最多20个请求。页面逐项提交，建议保持标签页打开；关闭标签页后，尚未提交的项不会继续自动提交。

### 来源怎么选

| 想获取什么 | 选择哪个来源 | 需要理解的范围 |
|---|---|---|
| 网站标题、链接、摘要 | Google 网页 | 默认第1页，深度参数10，实际数量可能更少；不是网页全文 |
| 某个主题的新闻 | Google 新闻 | 使用新闻搜索RSS；列表顺序不代表Google网页自然排名 |
| 某个地区当前热门话题 | Google 当前热搜 | 不是关键词历史热度曲线；仅选择此来源时无需填写关键词 |
| 商家名称、地址、电话、网站、评分等 | 地图商家 | 按下面的地图流程操作 |

页面仍有“Google 图片”，但图片沿用原流程，**本轮没有做图片的中台适配；测试新中台链路时先不要勾选图片。** 缺失字段表示未知，不应当作0或已核实的信息。

## 二、查询地图商家

1. 在“快速使用”中选择“地图商家”。
2. 选择“关键词搜索”，填写 `coffee`，城市选择“新加坡”，再选择搜索半径和语言。
3. 点击“搜索商家”，等待结果。
4. 查看名称、地址、电话、网站、评分、营业时间等可用字段，再点击“下载 CSV”或“下载 JSONL”。

想找某一类附近商家时，切换为“附近商家”，填写商家类型关键词，例如 `dentist` 或 `cafe`。需要指定位置时，展开“其他位置”，填写经纬度；自定义坐标会覆盖城市中心，重新选择城市会清除自定义坐标。

**地图结果按距离排序，每次最多约21家，不代表覆盖整个城市；不提供完整评论或独立地点详情。网站结果快照保留24小时，请及时下载。** 过期提示不代表中台中的数据已被删除。Maps的JSONL包含完整任务和商家数组，CSV按商家逐行导出。

## 三、读取已经保存的数据

### 查公开历史

1. 选择“历史数据”。
2. 按关键词、来源、地区或采集完成日期筛选；关键词可以留空。
3. 点击查询，展开对应记录，查看或下载；需要更多记录时点击“下一页历史请求”。

这个操作读取已有公开历史，**不启动新采集，也不是直接搜索中台全部数据。** 日期条件按采集完成时间筛选，不等于新闻发布日期。

### 按公开请求ID读取

1. 选择“按 ID 读取”。
2. 粘贴已有公开记录的“请求ID”。
3. 点击读取，查看完整记录或下载。

**请求ID和任务ID用途不同，不能互换。** 新中台任务的结果有私有归属，不一定出现在公开历史列表；应从本次任务结果或保留的任务进度恢复入口查看。不能把私有任务ID填到“公开请求ID”里，再根据404判断数据丢失。

## 四、数据到底存在哪里、从哪里读

新实时查询的流程是：

**网站提交查询 → 中台派单 → 采集服务获取数据 → 中台保存 → 网站从中台读回对应固定版本并校验 → 展示和下载。**

Web、News、Trends、Maps的新实时查询已使用这条链路。网站等到保存回执确认，并且实际读回的数据、身份和hash校验通过，才把任务结算为成功并开放结果下载。

“实时”表示按需触发，**不表示点击后立即可读，也不保证每次都绕过来源缓存。** 排队、采集、保存和校验需要时间。后续查看和下载复用已经验证的结果快照，不会每下载一次就重新采集，也不会自动换成中台最新版本。公开历史读取仍是已有搜索记录的读取流程，不能与新中台实时查询混为一谈。

普通同事不需要管理后台的持续采集、正文或旧上传开关；日常小范围测试从“快速使用”发起即可。历史数据和原采集管理任务不在本次实时查询迁移范围内。

## 五、测试成功怎么判断，失败怎么反馈

2026-11-13正式网站小样本已通过：**Web 3条、News 10条、Trends 10条、Maps 20家**，中台保存、固定版本读回/hash与CSV/JSONL深比较一致。正式域名读取和JSONL下载均返回200。这是小样本验收，不代表长期稳定性或固定响应时限。

同事复测时，先选一个来源、一个查询，按以下标准判断：任务成功完成、结果符合所选来源、CSV/JSONL能下载。需要验证中台接口时，再由开发同事核对保存回执、文档ID、版本ID和hash；仅页面能显示，不能证明其他项目的中台接入也通过。

| 遇到什么情况 | 怎么处理 |
|---|---|
| 网站进不去或要求登录 | 使用网站访问Key；不要填中台Collector/Consumer Key |
| 排队、处理中或请求超时 | 保留当前任务，使用“继续查看进度”；不要反复新建 |
| 没有搜索结果 | 先检查地区、关键词和范围；Maps可以扩大半径，0结果不一定是故障 |
| 401／403 | 核对登录、客户身份及授权，联系管理员 |
| 404 | 核对入口、ID类型和数据归属；公开读取入口不能读私有任务 |
| 429 | 降低频率，等待后沿用原任务或原幂等键重试 |
| Maps结果过期 | 24小时快照已过期，需要新查；不要据此判断中台数据被删 |

反馈时提供：**网站地址、来源、查询条件、任务ID或请求ID、操作时间、报错文字或截图。** 不发送真实Key或Authorization请求头。

## 六、给开发同事：几种Key有什么区别

| 凭据 | 谁使用、做什么 |
|---|---|
| 网站访问Key | 普通同事登录网站；外部API调用时通过 `X-SearchFlow-Access-Key` 传递 |
| SearchFlow客户API Key | 程序以 `Authorization: Bearer …` 调用本网站的客户API，用于身份和额度隔离 |
| 中台Collector Key | 采集服务领取指定任务、写入数据、查保存回执，仅配置在后端 |
| 中台Consumer Key | 网站后端向中台发起实时查询、读取获授权的结果，仅配置在后端 |

**四者不能互相替代。** 使用当前网站无需另建中台应用；其他独立项目接入中台，应申请自己的Collector/Consumer身份和授权，不复制本项目的Key。

接入本网站API时，搜索采用“创建任务 → 轮询 → 成功后读取/导出”；Maps使用独立的 `/v1/google/local/jobs` 接口。具体参数以网站“API工具”、地图接入示例和OpenAPI为准。网络中断时沿用原 `Idempotency-Key`，避免重复建单。

直接对接中台的开发同事还需确认：Web/News/Trends使用 `social_media_raw`，Maps使用 `google_maps_raw`，来源平台各自匹配；组织策略和Consumer授权都允许 `live_query` 及相应快照/原始载荷读取。取得Key不代表已经取得这些权限。
