# Google 数据分析网站需求文档 v1.0

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档名称 | Google 数据分析网站需求文档 |
| 版本 | v1.0 |
| 日期 | 2026-11-05 |
| 产品 | SearchFlow 工作台 |
| 本阶段目标 | 基于已有真实 Web、News、Trends 数据，完善展示、筛选、分析、下钻和数据质量说明 |
| 数据范围 | 现有数据库中已保存的公开 `google_web`、`google_news`、`google_trends` 请求 |
| 数据状态 | 真实历史数据；不发起新采集；不依赖 Whale 正式读回 |

本文只描述当前项目可以直接建设的网站数据层和分析层。GSC、GA4、Ads、Merchant、Local、AI Mode 和 Trends 历史数值曲线不属于本阶段已接入数据。

## 2. 产品目标

把当前网站从“查看几条真实历史记录”升级为“对已有真实数据进行可解释分析”。用户可以回答：

1. 哪些查询词已经有真实 Web 观测？
2. 目标网站和竞品在保存的 Web 结果中出现了多少次、排名如何变化？
3. News 和 Trends 当前保存了什么内容？哪些字段未知或未覆盖？
4. 每个分析结论对应哪些原始请求和结果？
5. 当前数据能支持什么结论，哪些结论暂时不能支持？

## 3. 当前基线

### 3.1 已存在的数据

当前旧库已经保存：

- Web 请求及自然搜索结果。
- News 请求及新闻结果。
- Trends 请求及热门话题、相关报道。
- 查询词、请求状态、完成时间、页码和响应内容。
- Web 结果的 URL、标题、摘要、自然位置和源绝对排名。
- News 结果的标题、来源、列表顺序、链接和链接解析状态。
- Trends 话题、热门顺序、原始搜索量标记和相关报道。

Web 的实际获取链路是现有 OpenSERP；News 和 Trends 是 RSS 观测。网站须显示具体来源，不把三者统称为 Google 官方业务 API。

### 3.2 当前明确限制

- 设备、精确位置、登录态、源观测时间可能没有保存，必须显示“未知”。
- News 列表顺序不等于 Google 自然排名。
- Trends 当前数据是 Trending Now RSS 热门话题，不是关键词历史热度曲线。
- 旧历史数据当前属于过渡预览，不等于 Whale 正式读回。
- 没有数据表示“未覆盖”，不能显示为 0。
- 失败请求、空结果、未知字段和未接入来源必须分开。

### 3.3 已上线与待建设

| 能力 | 当前状态 | 本项目处理 |
|---|---|---|
| Google 研究历史卡片 | 已上线；每来源默认展示最近 5 次公开请求 | 补筛选、分页、字段状态和请求详情 |
| 搜索分析数据总览 | 已上线基础汇总 | 补统一口径、分来源质量和下钻 |
| 搜索分析排名与竞品 | 已上线同条件基础比较 | 补域名/URL筛选和证据下钻，复核缓存与未知排名 |
| News 独立分析 | 有来源汇总和原始结果，缺专项页面 | 建发布者、链接解析及重复记录分析 |
| Trends 独立分析 | 有热门话题和报道，缺专项页面 | 建话题/报道统计和明确的未覆盖状态 |
| Whale 固定版本读回 | 未接入网站 | 本阶段不处理 |

2026-11-05 生产只读快照：公开历史请求 Web 31,676、News 8,126、Trends 28。该数量是当时数据库快照，不作为产品固定数字或全网覆盖声明。

## 4. 用户与使用场景

| 用户 | 主要任务 |
|---|---|
| SEO/内容人员 | 查询词、目标域名和竞品的 Web 结果比较 |
| 品牌/市场研究人员 | 查看 News 和 Trends 的真实记录及来源限制 |
| 数据分析人员 | 核对请求数量、成功率、字段完整度和重复情况 |
| 管理人员 | 判断当前数据覆盖范围和下一步是否需要扩大采集 |

## 5. 功能范围

### 5.1 数据展示

#### 5.1.1 Web 数据卡片

每次请求必须展示：

| 字段 | 展示要求 |
|---|---|
| 查询词 | 显示原始 query；缺失显示“未知” |
| 来源 | Google Web |
| 请求状态 | 成功、空结果、失败、超时或未知 |
| 完成时间 | 使用数据库保存的完成时间，并标明 UTC |
| 国家/语言 | 有值显示实际值，无值显示“未知” |
| 设备 | 有值显示实际值，无值显示“未知” |
| 精确位置 | 当前没有记录时显示“未知” |
| 缓存状态 | 有真实字段才显示，否则“未知” |
| 结果数量 | 只显示实际保存数量 |
| 自然位置 | 只使用明确的 organic position |
| 源绝对排名 | 与自然位置分开显示 |
| URL | 显示原始或规范化后的实际 URL，并允许打开 |
| 标题 | 缺失显示“标题未知” |
| 摘要 | 缺失显示“摘要未知” |

禁止：把没有排名的结果显示为第 10、101 或其他推测位置；把未返回的 URL 显示为“排名下降”。

#### 5.1.2 News 数据卡片

每次请求必须展示：

- 查询词。
- Google News 来源。
- 请求状态和完成时间。
- 新闻标题。
- 发布者名称。
- 发布者 URL（如未解析显示“未知”）。
- 新闻链接及链接解析状态。
- News 列表顺序。
- 摘要（有值才显示）。

页面固定提示：**News 列表顺序不是 Google 自然排名；新闻结果不代表完整媒体报道数量。**

新闻发布时间只有在源字段明确提供且能确认语义时展示。当前预览映射未提供独立发布时间，实施前须核查旧响应字段；不得使用请求完成时间代替新闻发布时间。

#### 5.1.3 Trends 数据卡片

每次请求必须展示：

- 热门话题。
- 热门顺序。
- 原始搜索量标记。
- 相关报道数量。
- 相关报道标题、来源和链接。
- 请求状态和完成时间。

页面固定提示：**当前 Trends 数据是热门话题观测，不是关键词历史热度曲线，也不是绝对搜索量。**

### 5.2 统一状态语义

所有数据记录和分析结果使用以下状态：

| 状态 | 含义 |
|---|---|
| available | 有真实数据 |
| true_zero | 源明确返回 0 |
| unknown | 该字段没有保存或源未提供 |
| not_observed | 本次没有观测到该字段 |
| not_covered | 当前数据范围没有覆盖 |
| outside_observed_depth | 超出本次保存深度 |
| source_error | 源请求失败 |
| expired | 数据或权限已过期 |

前端显示规则：

- `true_zero` 显示“0”。
- `unknown` 显示“未知”。
- `not_covered` 显示“未覆盖”。
- `source_error` 显示“源请求失败”。
- `outside_observed_depth` 显示“超出观测深度”。
- 空字符串、null 和缺失字段不能自动转为 0。

## 6. 数据分析页面

现有“搜索分析”页面继续保留，并补充以下能力；“Google 研究 → 真实历史数据”作为原始数据查看入口。

### 6.1 数据总览

必须显示当前筛选范围内：

- 请求总数。
- 成功请求数。
- 空结果请求数。
- 失败请求数。
- 覆盖查询词数。
- Web、News、Trends 各自请求数。
- 结果记录数。
- 唯一 URL 数。
- 重复 URL 记录数。
- 最早和最晚完成时间。
- 数据生成时间。
- 当前筛选条件。

每个数字必须可以查看口径：分子、分母、时间范围、来源和是否包含未知值。

### 6.2 排名与竞品比较

仅对 Google Web 自然结果启用排名分析。News 和 Trends 不进入自然排名比较。

用户可以输入：

- 目标域名，1 个或多个。
- 竞品域名，最多 10 个。
- 查询词。
- 国家。
- 语言。
- 设备。
- 时间范围。
- 页码或观测深度。

输出：

- 每个域名的出现次数。
- 每个域名的有效观测次数。
- Top 3 覆盖率。
- Top 10 覆盖率。
- 最佳自然位置。
- 最差自然位置。
- 平均位置和中位位置。
- 目标域名与竞品的差值。
- 目标域名出现的具体 URL。

公式：

```text
Top K 覆盖率 = 目标域名进入前 K 的有效 Web 观测次数 / 具备可比较排名的有效 Web 观测次数
```

要求：

- 只比较相同来源、相同查询词、相同国家、相同语言、相同设备、相同页码和相同时间窗口。
- 失败请求不进入有效分母，但必须单独显示失败数量。
- 缓存数据如果无法确认是否为新观测，不能作为独立样本重复计入。
- 未知排名不作为“没有排名”处理。
- 结果不称为 Google 用户真实曝光或流量份额。

### 6.3 URL 出现次数和排名变化

对精确 URL 统计：

- 出现请求数。
- 覆盖查询词数。
- 首次出现时间。
- 最后出现时间。
- 最佳自然位置。
- 最差自然位置。
- 平均自然位置。
- 标题变化次数。
- 摘要变化次数。
- 最近一次是否出现。

相邻两次同条件观测可计算：

- 新出现 URL。
- 本次未出现 URL。
- 排名上升。
- 排名下降。
- 排名不变。
- 结果重合率。
- 标题变化。
- 摘要变化。

只有前后两次都存在、且都有明确自然位置时，才计算排名变化。若相同查询词在历史中没有第二次可比请求，页面显示“样本不足”，不绘制变化趋势。

### 6.4 News 分析

News 单独统计：

- 请求数。
- 新闻结果数。
- 发布者名称分布。
- 已解析和未解析链接数。
- 精确 URL 出现次数。
- 相同标题和 URL 的重复记录。
- 有明确发布时间和没有明确发布时间的数量。

重复仅按可验证的精确 URL 或明确的标题规则标记为“重复候选”；没有出版者正文、canonical 或人工核验时，不声称已准确识别转载和独立报道。不输出“全网媒体占有率”，不把 News 列表顺序当成自然排名。

### 6.5 Trends 分析

Trends 单独统计：

- 热门话题请求数。
- 话题数量。
- 话题出现次数。
- 热门顺序变化（仅在同一来源和同一口径下）。
- 原始搜索量标记分布。
- 相关报道数量。
- 相关报道 URL 和发布者。

本阶段不输出：

- 历史热度曲线。
- 关键词环比或同比增长率。
- 绝对搜索量。
- 市场需求份额。

## 7. 查询筛选

所有分析页面必须支持：

| 筛选 | 规则 |
|---|---|
| 来源 | Web、News、Trends、全部来源 |
| 查询词 | 精确或包含匹配；不静默合并同义词 |
| 域名 | 按实际 hostname 筛选 |
| 时间 | 使用 UTC，范围为左闭右开 `[from, to)` |
| 国家 | 缺失值可单独选择“未知” |
| 语言 | 缺失值可单独选择“未知” |
| 设备 | 缺失值可单独选择“未知” |
| 状态 | 成功、空结果、失败、超时、未知 |

筛选条件必须显示在结果顶部，并随导出文件保存。
域名筛选对 Web 结果和 News 报道链接适用；Trends 话题本身没有域名，仅能按相关报道域名筛选，页面须明确标记。旧记录设备为未知时，选“移动端”不能把它纳入移动端样本。

## 8. 原始数据下钻

分析结果必须支持以下下钻路径：

```text
汇总指标
  → 查询词 / 域名 / URL
    → 请求记录
      → 原始请求条件
        → 原始结果列表
          → 标题、摘要、URL、排名或顺序
```

每个请求详情必须显示：

- request_id。
- 来源。
- query。
- 请求状态。
- 完成时间。
- 国家、语言、设备、页码。
- 缓存状态。
- 结果数量。
- 原始字段存在性。
- 当前数据范围和限制说明。

下钻不能展示其他租户的私有任务或私有结果。

## 9. 数据质量页面

新增或完善“质量与用量”区域，显示：

### 9.1 来源说明

- 来源名称。
- 来源类型：真实历史请求、数据库投影或过渡预览。
- 数据库字段版本。
- 最早记录时间。
- 最新记录时间。
- 最近一次读取时间。
- 是否发起新采集：本阶段必须为否。

这一区域展示**旧库历史数据质量**。现有 Google 域“质量与用量”若查询的是正式观测投影，必须与旧库质量分栏，不能用未接入状态覆盖旧库的实际请求数。

### 9.2 覆盖情况

- 已覆盖查询词数。
- Web、News、Trends 各自请求数。
- 各来源成功、空结果和失败数。
- 有排名的 Web 结果数。
- 有标题的结果数。
- 有摘要的结果数。
- 已解析和未解析的 News 链接数。
- 有话题和相关报道的 Trends 记录数。

覆盖率只相对于当前数据库中已保存的查询词和请求计算，不宣称覆盖全部 Google 搜索。

### 9.3 字段质量

每个字段显示：

- 已提供数量。
- 缺失数量。
- 未知数量。
- 适用记录数量。
- 计算口径。

例如：

```text
Web 自然排名：有值 8,000 / 适用结果 9,000
News 发布者 URL：已解析 500 / 新闻结果 800
Trends 数值历史曲线：未覆盖
```

### 9.4 限制说明

质量页面必须固定显示：

- 当前数据来自已有历史记录。
- 不代表全部 Google 用户看到的结果。
- News 顺序不是自然排名。
- Trends 不是历史热度曲线。
- 设备、精确位置、登录态等没有记录时为未知。
- 旧库数据尚未完成 Whale 正式读回。

## 10. API 与数据接口要求

### 10.1 原始数据接口

保留并完善现有过渡接口：

```text
GET /v1/google/legacy-observations
```

支持参数：

- `source=google_web|google_news|google_trends`
- `query`
- `domain`
- `from`
- `to`
- `classification`
- `limit`
- `cursor`

接口要求：

- 只读。
- 默认限制返回数量。
- 使用 UTC 时间。
- 返回 `has_more` 或游标状态。
- 不返回客户私有数据。
- 不把缺失字段转换成 0。
- 返回 `provenance`、`coverage`、`quality` 和 `limitations`。

### 10.2 分析接口

复用已上线的公开历史分析接口，扩充字段和筛选能力：

```text
GET /api/product/analytics/summary
GET /api/product/analytics/overview
GET /api/product/analytics
```

新增 News、Trends 和请求详情时，使用明确标记旧库来源的接口，避免与正式 Whale 观测接口混淆：

```text
GET /v1/google/legacy-analysis/news
GET /v1/google/legacy-analysis/trends
GET /v1/google/legacy-analysis/requests/{request_id}
```

具体路径作为研发评审提案，冻结 OpenAPI 后实施。`/api/product/analytics*` 保持现有网站访问门禁；`/v1/google/legacy-*` 保持网站访问 Key 加客户 Bearer。两组接口都必须在 SQL 层排除私有任务；不能因页面跳转改变数据权限。

所有新增或扩展后的分析响应必须包含：

- `generated_at`。
- `observed_from`、`observed_to`。
- `source`。
- `filters`。
- `sample_size`。
- `eligible_denominator`。
- `missing_counts`。
- `availability`。
- `methodology_version`。
- `limitations`。

### 10.3 导出

支持 JSON 和 CSV。导出必须包含：

- 原始查询词。
- 来源。
- request_id。
- URL 或话题。
- 排名或顺序。
- 标题、摘要或报道信息。
- 完成时间。
- 筛选条件。
- 数据来源。
- 字段状态。
- 生成时间。

导出文件不能省略“未知、未覆盖、失败”等状态。

## 12. 权限和安全

- 页面继续使用现有网站访问 Key 和客户 Bearer 机制。
- 公开历史数据也必须经过当前网站访问层。
- 所有查询和分析 SQL 使用只读事务。
- 查询参数必须绑定，不能拼接 SQL。
- 客户私有任务必须在数据库层排除。
- 导出和详情接口重复执行租户和权限校验。
- 不在日志、页面或导出中显示 OAuth、Collector Key、Consumer Key 或密码。

## 13. 性能要求

以下为目标值，尚未完成该版本的压测，不代表当前网站已达到：

| 场景 | 目标 |
|---|---|
| 首页数据摘要 | 已有缓存情况下 3 秒内 |
| 常规筛选 | 5 秒内返回 |
| 冷分析 | 15 秒内返回，页面显示“正在统计” |
| 分页 | 单页最多 50 条 |
| 详情 | 3 秒内返回单个请求 |
| 导出 | 大结果异步生成或明确限制，不阻塞页面 |

分析页面只读取已保存数据，不得因为用户打开页面而启动采集。

## 14. 验收标准

### 14.1 数据展示验收

- Web、News、Trends 各展示真实已保存记录。
- Web 自然位置和源绝对排名分开。
- News 列表顺序不显示为自然排名。
- Trends 不显示虚假的历史曲线。
- 未知字段显示“未知”。
- 无覆盖显示“未覆盖”。
- 失败请求不显示为成功或 0 条结果。

### 14.2 分析验收

- 可按来源、查询词、域名、时间筛选。
- Web 支持目标域名和竞品比较。
- 可查看 URL 出现次数和排名变化。
- News、Trends 不进入 Web 排名统计。
- 所有比例显示分子、分母和有效样本数。
- 未知排名不被当成掉出排名。
- 同一 URL 多次出现可以保留观察记录，但不会重复计为唯一 URL。

### 14.3 下钻验收

- 汇总数字可以下钻到查询词。
- 查询词可以下钻到 request_id。
- request_id 可以查看完整保存结果。
- 结果详情包含来源、时间、条件和字段状态。
- 私有数据无法被其他租户查询、搜索或导出。

### 14.4 数据质量验收

- 页面显示来源、时间范围和生成时间。
- 页面显示当前覆盖查询词数和请求数。
- 页面显示成功、空结果、失败和未知的数量。
- 页面固定显示 News、Trends 和未知字段限制。
- 不因缺失字段补 0 而提高覆盖率。

### 14.5 真实样本与回归验收

- 固定至少 1,000 条真实结果记录，覆盖至少 100 个查询词；对不足的来源只声明实际样本范围，不借 Web 样本为 News 或 Trends 通过验收。
- 对至少 200 套真实 Web 结果核对自然位置、源绝对排名、重复 URL 和跨查询出现。
- 对 News 未解析链接、无发布时间、转载/重复标题和 Trends 原始流量标记建立反例。
- 使用独立数据库验证公开/私有任务隔离、筛选、分页、下钻和导出；随后运行项目真实全量回归。
- 上线后只读核对 Web、News、Trends 请求数、原始库记录数、分析投影数和页面显示数；允许口径不同，但差异必须可解释。

## 16. 本阶段不做

- 不做 Whale 正式入库和读回。
- 不开启自动采集。
- 不接入 GSC、GA4、Ads、Merchant、Local。
- 不把 Trends 热门话题改造成历史趋势曲线。
- 不抓取新闻正文。
- 不生成 Google 全网覆盖率。
- 不生成真实流量、曝光量、收入或因果结论。
- 不把供应商估算、广告数据和 Web 排名合并成一个 Google 总指标。

## 17. 完成定义

当以下条件全部满足，阶段一至三可视为完成：

1. 用户可以在一个网站中查看 Web、News、Trends 三类真实历史数据。
2. 用户可以按来源、查询词、域名和时间筛选。
3. 用户可以比较目标域名和竞品的 Web 自然结果。
4. 用户可以查看 URL 出现次数和可比排名变化。
5. 用户可以区分真实值、未知、失败和未覆盖。
6. 每个分析结果都能下钻到 request_id 和原始保存结果。
7. News 和 Trends 的限制在页面上明确展示。
8. 导出数据与页面数据使用相同筛选条件和字段语义。
9. 网站不因分析页面打开而发起采集请求。

本文件是后续实施与验收的需求稿；除第 3 节注明的现状外，其余接口扩展、页面和目标值均待开发与验证。
