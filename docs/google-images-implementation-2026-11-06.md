# Google Images 数据采集上线（2026-11-06）

已完成图片搜索的手动任务、保存、查看、分页、CSV/JSONL 导出和客户异步 API。复用现有 OpenSERP 的 `/google/image`，每个关键词只请求首批、最多 20 条；不下载原图，不增加图片分析、OCR 或 Lens。实际返回数量以上游为准。

本次授权为用户在可行性研究后要求“深度实现”。持续供给、正文、Whale 自动领取与上传均保持关闭。所有真实搜索均由本轮有限手动验收任务触发，没有开启后台自动采集。

## 功能及数据语义

- 新 `google_images.py` 独立调用图片路由，核对查询、Google 引擎、请求 ID、响应版本、结果类型与 envelope；不再依赖网页搜索入口上未声明的 vertical 参数。非图片结果不能混入图片数据。
- 独立读取 `image.url/thumbnail/width/height` 和 `source.page_url/domain`。图片、来源网页、缩略图是三个字段；宽高只采信上游正整数，MIME、未提供的时间及字段保持未知。
- 每条出现保留独立顺序及原始字段，同图出现在不同网页时不提前合并。上游 rank 与返回序号分别保存，全局排名未知，不把图片网格当成 Web 自然排名。
- 图片 URL 使用保守的精确 URL 身份，保留 CDN 参数及原编码，不套用网页跟踪参数清理；敏感参数不会泄露。`public_fields()` 修正为无须脱敏时不重写 URL，避免把 `%20` 改成 `+`。唯一 URL 只计首次贡献，重复出现记录保留。
- 使用现有代理调度、健康与冷却、请求存储；图片使用独立缓存键及全局 PostgreSQL 会话锁，图片并发为 1。私有任务缓存隔离，暂停后不启动新请求，一次性任务失败会结束；全局图片锁忙时等待后续调度，不误报成功。
- 保存原始结构化响应、请求/接收时间、查询条件、错误、覆盖及部分解析状态；图片采集方式标明 `openserp_google_images`。没有真实图片发布时间，不填充假日期。

## 网站与接口

首页增加 Google Images 入口；新建任务支持图片来源、地区、语言与一次性预算，确认页显示每词 20 条上限。数据集可按图片来源及原有条件筛选、翻页、查看已保存字段。图片卡片分开提供图片链接和来源网页，展示上游尺寸；预览仅在有缩略图时由用户主动加载，不自动抓原图。

实际样本的上游没有返回缩略图，页面明确提示，可打开图片链接查看。未伪造预览地址或把原图冒充缩略图。

接口：

| 接口 | 已接通内容 |
| --- | --- |
| `/api/serp/tasks` | 创建/控制图片采集任务，沿用管理鉴权 |
| `/api/serp/results`、`browse-requests`、`export` | 图片结果、请求与同筛选导出，排除客户私有数据 |
| `/v1/search`、`/v1/jobs/{id}` | `source=google_images`，异步任务、幂等、配额及租户隔离 |
| `/v1/jobs/{id}/export` | 图片 API CSV/JSONL，完整结果归属于客户任务 |
| `/v1/google/legacy-data` 及详情 | 已存公开图片请求的规范化读取，不冒充 Whale 正式观测 |
| `/v1/capabilities`、`/v1/openapi.json` | 图片来源及实际每词 20 条请求深度 |

网页用户 CSV 增加图片字段及“图片原始记录 JSON”，共 50 列，原字段顺序保留；用原始记录列保留空值及全部图片字段。客户图片 CSV 为 14 列（含 `record_json`），其他客户来源的七列 CSV 不变。JSONL 保留完整记录，不把缺失尺寸变为 0。

本轮不新增图片排名分析。现有 analytics 可见范围明确排除 google_images，避免把图片请求错误投影为“零个网页结果”；图片在数据集与历史接口独立读取。首页既有分析汇总说明仍只覆盖 Web/News/Trends。

图片平台交付未开放：创建任务时禁止图片自动加入 Whale 队列；显式图片上传返回不支持，“上传全部”也排除图片，不把图片塞进旧 Web/URL 协议。旧 Web 完整快照质量 100 的验证与图片交付是不同事项，本轮没有向 Marsyoo 新写入图片文档。

## 真实验收

首轮通过真实网站向导提交一次性任务：

- `41fad461-d490-4800-8059-9b542bb30162`，US/en，关键词 solar panel diagram、Singapore skyline、red panda habitat，成功次数预算 3。
- 首轮 2 次 HTTP 200，各 20 条；solar panel diagram 一次 HTTP 429。错误与 40 条成功结果均保存，任务状态 failed，没有自动无限重试。
- 对失败词只创建一次手动重试 `068f6b8f-660e-4c23-a782-3ce56a55e5f7`，HTTP 200、20 条、任务 completed；原失败证据保留。

目前公开图片结果 **60 条**，均有图片链接和来源页，55 条提供宽高、5 条未知，缩略图均未提供。不能据此宣称长期成功率或稳定产能。

网站实际下载 CSV 60 行 / 50 列、JSONL 60 行，逐条验证原始图片记录及来源页一致。实际分页 25 + 25 + 10，最后一页禁用下一页。桌面、390px 手机均检查，手机 document 宽度 390，无横向溢出；截图已经人工视觉检查。首页四来源入口、图片选择、任务创建与结果卡片均真实操作。

客户 API 另提交一条私有图片搜索，job `58f439ea-7afd-4c36-80a0-34faa3e580d8`：

- HTTP 202 → succeeded，20 条图片结果，成功用量增量 1，reserved=0。
- 重放相同 Idempotency-Key 返回相同 job、reused=true，无重复采集或扣次。
- 私有 CSV 20 行 / 14 列与 JSONL 中 20 个图片记录逐项一致。
- 公开图片列表仍为 60 条，搜索该私有查询返回 0 条；无客户 Key 读取私有 job 返回 401。
- 三个旧来源的正式读取均 HTTP 200。规范化图片历史接口返回 4 个公开请求（含一次失败）及 60 条 occurrence；不暴露私有请求。

最终实际新增图片请求 **5 次：4 成功、1 次 429，共 80 条结果出现记录；其中公开 60、私有 20**。这不是 80 个已下载文件，也不能直接当作 80 个全球唯一图片。
