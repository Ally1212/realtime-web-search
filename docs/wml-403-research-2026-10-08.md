# WML 403 调查（2026-10-08）

结论：现有服务器和私有代理下，WML 请求仍被 Google 拒绝。403 不足以证明某个 IP 永久封禁，也不足以证明接口全球关闭。公开资料有 Google 403、WML 验证挑战、按出口 IP 不同而表现不同的案例；本次没有找到与现有 WML 403 模板完全对应、且根因已被证实的公开案例。

## 本系统证据

- 08:52（UTC+8）在生产服务器通过私有代理测试3次（2英文、1中文），全部 HTTP403，真实结果0。
- 3次代理 host 分组哈希不同，但没有核验实际出口 IP，不声称3个独立出口。
- 响应标题 `Error 403 (Forbidden)!!1`；正文 `Your client does not have permission to get URL /wml/search...`。
- 服务器证据 `/app/state/wml-retest-20261008T005216Z/report.json` 与同目录 HTML。
- 昨夜普通 Google 网页搜索经 OpenSERP 成功入库15648篇；这是通道总体可用证据，不是与本次 WML 相同 IP、相同时刻的对照。
- 私有代理请求的源地址通常为代理出口，不能据此认为用户家庭 IP 或 Azure 服务器出口被封。

## 查阅来源与证据边界

1. Google 官方：[异常流量帮助](https://support.google.com/websearch/answer/86640?hl=en)。官方明确列出程序、采集器、共享 VPN/ISP 的自动搜索；某些网络会被整体限制。该文解释 unusual traffic/reCAPTCHA，不是 WML403 的专门公告。已从生产服务器成功读取HTTP200全文。
2. MDN：[403含义](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/403)。服务器理解请求但拒绝处理；不包含具体封禁对象或时限。已读取全文。
3. SearXNG：[Google引擎源码](https://github.com/searxng/searxng/blob/master/searx/engines/google.py)。查阅时仍构造 `/wml/search` 和 Nokia UA。这证明项目实现存在，不证明当前所有用户可用。
4. Octos：[PR2619](https://github.com/octos-org/octos/pull/2619)，2026-09-29。作者报告同类 WML 请求随客户端指纹/请求头不同，可能返回 unusual traffic 或真实结果，并报告自己的实时测试成功。属作者测试报告，非Google官方确认；不能推定10月8日我们的代理可用。
5. SearXNG：[issue6359的IP观察](https://github.com/searxng/searxng/issues/6359#issuecomment-5057046857)，2026-07-23。用户称两个IP重新有结果，其他代理IP仍失败。这是普通Google引擎讨论，不能冒充本次WML403已定位案例。
6. SearXNG：[issue2972](https://github.com/searxng/searxng/issues/2972)。高分页请求导致Google403。我们本次请求首页，因此该具体触发因素不适用；用于说明403原因不唯一。

检索渠道包括GitHub问题搜索、Bing及上述原始资料；Bing精确关键词未给出有效WML403案例。Google直接检索和部分站点从本机超时，官方资料改由服务器读取成功。没有将搜索结果摘要当作已核实根因。

## 如何判断IP因素

要有判别力，需在遵守既有代理预约与间隔的条件下做对照：固定同一经核验出口IP，分别测试普通浏览器Google搜索和WML；再固定WML请求内容，换经核验独立出口。普通搜索成功/WML失败说明没有全面禁止该出口搜索，但仍可能是IP与端点组合限制。只有换出口恢复、其余变量保持不变，才明显支持IP因素。当前尚无这组严格对照证据，不以403本身断言永久封IP或等待多久可恢复。
