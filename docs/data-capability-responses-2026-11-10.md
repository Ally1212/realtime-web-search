# 来源响应独立保存与交付（2026-11-10，本地候选）

本阶段补齐“来源已经返回，但解析或计费核对失败后丢失原响应”的缺口。响应记录独立于规范化观测：保存响应不代表曲线解析成功、不产生订阅事件，也不代表平台已接收。未部署、未真实调用供应商、未改变生产开关。

## 显式启用

新增 `data_capability_responses.ResponseStore(service, grant_for)`，必须由可信启动代码显式 `initialize()`，随后同时传给 `CapabilityExecutor(..., response_store=store)` 和 `CapabilityRuntime(..., response_store=store)`。没有自动初始化、线程、生产挂载或旧库迁移。

默认单响应最多16 MiB、共享原文逻辑配额128 MiB、最多1000条活跃记录、最长24小时；TTL还受当前许可到期及来源保留天数约束。策略摘要存入独立策略表；不同进程使用不一致策略时拒绝工作。所有响应写操作使用同一 PostgreSQL 事务咨询锁，在外部调用前原子预留空间，按实际脱敏JSON大小结转，未使用预留在执行结束释放。到期原文在下一次预留或显式 `purge_expired()` 时清除；当前候选没有自动清理调度器。

原文保留必须由可信来源授权中 `raw_response_retention_allowed=true` 明确准许，不能通过客户参数开启。SerpApi 候选开启 `retain_raw` 后要求响应仓已挂载、权限和容量就绪，否则新任务503；事务内仍会重查，空间不足不调用来源。无原文保留许可时不得绕过门禁收集响应。

## 保存与失败语义

- SerpApi 在计费核对和曲线解析之前保存已脱敏JSON及HTTP状态、请求/接收时间、范围核验、完整性、保留状态和摘要。已知实际费用的解析失败仍记失败及实际费用；未知费用保持待对账并暂停同来源账户派发，不自动再收费调用。
- 仅保留完整且请求范围可核验的JSON；无法解析、范围不符或不完整时只保存明确的 `not_retained` 原因，不把半截或其他范围的内容当完整响应。Secret值、编码变体及含密钥的字段名脱敏；没有保存原始HTTP字节流。
- `payload_hash` / `snapshot_hash` 都基于规范JSON，`hash_encoding=sha256-canonical-json-utf8-not-source-bytes`。保存成功后不可替换，重复相同响应幂等。响应中的 `normalized_fact_status=not_asserted` / `platform_delivery=not_submitted` 不会因响应可下载而提升。
- 绑定租户、任务和原始执行lease；取消清除原文，操作员可调用内部 `erase()` 留下清除记录；没有客户删除接口。读取、导出生成后发送前均复核当前权限、保留期、取消及快照摘要。损坏时拒绝交付。

## 客户接口

沿用前置访问门和客户 Bearer，不新增公开路由：

| 请求 | 行为 |
|---|---|
| `GET /v1/jobs/{id}/response` | 完整响应信封及固定摘要，可能是明确未保留的元数据 |
| `GET /v1/jobs/{id}/response/export?format=zip&snapshot_hash=…` | JSON / JSONL / CSV / manifest / ZIP；默认ZIP，建议固定摘要 |

其他租户404；尚未保存409；撤权409；取消或已清除410；挂载runtime但未挂载响应仓503；格式/多余参数400，写请求405。未产生规范化观测时原 `/data` 仍返回409，不会因为有响应记录变成成功。

OpenAPI 1.4.0、capabilities及fields加入上述合同。五种格式包含完整响应信封；CSV的 `record_json` 是完整JSON，未拆成曲线点或冒充业务事实。ZIP同时包含四份文件和字节数/SHA256清单。`data_capability_response_export.verify_bundle()` 要求调用方提供期望响应ID与快照摘要，独立校验身份、内容、文件摘要、JSONL及CSV一致性，声明规范化事实数量为0。共享已有导出并发限制，完整构建及权限复查成功才发送。

## 验证与边界

专项使用独立 PostgreSQL、Redis 和本地HTTP，供应商响应均为合成fixture。覆盖并发空间预留、策略冲突、重启读取、TTL清除、当前撤权、跨租户、取消和清除不可重写、数据库保存故障、超限/非有限值/敏感字段、200 KiB以上响应、五格式及损坏拒绝；客户HTTP覆盖付费解析失败、未知账单、准入前拒绝和导出后撤权。最终数量见需求文档第九阶段与 `state/data-capabilities-20261110/response-regression-final/`。

这里的配额是应用原文逻辑字节，不是数据库物理磁盘保障；JSONB、索引、元数据和清除审计占用额外空间，墓碑未设自动归档。没有完成外部备份恢复后的墓碑重放、下载文件远端召回或真实供应商响应验收。网页失败响应查看入口、正式启动挂载、真实许可/预算/计费、其他三能力适配、平台各域读回和规模/七天验收仍待完成。

后续第十阶段已补本地网页响应查看与下载入口，覆盖任务/连接切换和撤权清空；见 [网页报告](data-capability-response-ui-2026-11-10.md)。前文网页入口待完成为第九阶段历史状态，生产挂载及真实来源验收仍未完成。

## 后续：多段响应持久保存

第十二阶段新增独立 checkpoint→封存日志，同一任务最多8段共用原16MiB预留，完整且范围可核验的脱敏首段在继续调用前落盘；后段不可保留或失败不覆盖首段。单次save保持原不可变合同。封存前409，结束后原响应及五格式接口交付整个固定日志；过期lease可显式恢复封存，挂载runtime的维护仅处理本人租户，均不重发来源或生成事实。取消/撤权/清除/配额/摘要保护继续有效。详见 [分阶段来源响应](data-capability-source-calls-2026-11-10.md)，封存不是完整回答或最终费用证明。
