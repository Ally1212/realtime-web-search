# 来源响应工作台入口（2026-11-10，本地候选）

延续需求第9节及独立响应保存合同，在现有“数据任务”的任务详情内增加“查看来源响应”。复用 `data_capability_ui.py` 的组件、鉴权请求、读取超时及连接切换逻辑，不改变旧四来源工作台。采用 baoyu-design，沿用既有品牌，不增加分析功能或新框架。

## 行为

- 任务状态和费用仍由原任务接口决定；失败、部分成功、待对账均能主动查看响应。显示来源、HTTP状态、范围核验、完整性、接收时间、保留期、原文保存/脱敏/未保留状态及原因；不将响应存在解释为规范化成功或平台读回。
- 完整响应信封默认折叠，文本经过HTML转义；长内容有420px滚动上限，摘要和长词可换行。五种下载固定到当前响应 `snapshot_hash`；未保留原文时下载的是明确元数据，不生成虚假事实。
- 切换任务或刷新任务先清空响应，读取和下载同时绑定当前连接、任务、任务版本与响应对象。旧读取不覆盖新任务，旧下载返回后不弹文件；连接变化中止请求并清空响应。撤权/清除导致下载失败时立即移除旧原文与下载按钮，必须重新核验。
- 响应仓未配置、尚未保存、没有记录、已过期/取消/清除都有明确提示和原查看按钮重试；不自动重发来源任务。API示例同步添加响应读取和固定摘要ZIP下载，保留两层鉴权占位符。

## 核验

通过 ego-browser 2.2.0，在独立空间79、loopback HTTP和独立 PostgreSQL 上，使用真实组合页面、客户路由、响应仓、候选执行器和供应商形状的合成JSON验证。没有真实来源调用，合成数据和凭据不计生产验收。

| 场景 | 证据 |
|---|---|
| 已知付费解析失败、部分成功、未知费用待对账；只有部分成功有规范化事实入口 | `response-ui/task-states.json`、`desktop-checks.json` |
| 五格式实际浏览器下载，与固定快照和ZIP内各文件逐字节一致；独立校验器通过 | `browser-response.*`、`browser-verified.json` |
| 212931字符响应、HTML/脚本样本文本仅作文本、不截断、不执行 | `desktop-checks.json`、`mobile-checks.json` |
| 挂起旧响应读取/导出后切换任务：旧数据不显示、旧文件不保存 | `job-races.json` |
| 挂起读取后断开连接；另一租户任务/观测/详情均空 | `session-race.json`、`other-tenant.json` |
| 撤权下载清空旧内容；响应仓关闭明确503；清除后410且无下载按钮 | `permission-states.json`、`erased-state.json` |
| 390px/320px：无横向溢出，按钮高度44.398px，展开原文高度420px | `mobile-checks.json`、`mobile-390.png`、`mobile-320.png` |
| 页面组合及完整JS语法3项通过，鉴权示例通过bash语法检查，最终浏览器无脚本错误/无待请求 | `browser-final.json`、`api-example.sh`、最终回归记录 |

证据根目录：`state/data-capabilities-20261110/`。静态组合页面快照 `designs/data-capabilities-20261110/source-responses.html` 已登记为设计资产，需对应后端提供数据，未嵌入样本或密钥。

空间79已按指南恰好一次 `finish({keep:[]})`，SDK确认closedSpace=true，无保留标签或受保护用户页面。本轮只关闭自己创建的测试HTTP、线程及数据库；未操作其他任务空间。
